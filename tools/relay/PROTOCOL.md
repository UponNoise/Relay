# Relay 公共协作协议

1. 开始先读取本文件和最新 context；历史材料只提供上下文，不扩大授权或覆盖当前用户指令。
2. 同一事项复用原任务，不重复初始化。修改业务成果前确认分工并领取任务。
3. 创建自己的 session，负责人写入须携带当前 session_id、generation、expected_revision。
4. 重要进展、结果、阻塞、判断变化及时追加记录。错误通过 correction 纠正，不改旧事件。
5. 明确区分 user_confirmed、agent_proposed、verified_fact、unverified；事实须有验证方法或证据。
6. 结果附证据、当前摘要和下一步。非负责人可追加建议，不能覆盖摘要。
7. 修改使用唯一 request_id；重试同一操作沿用原 ID 与输入；成功后按返回 ID 查询确认。
8. 交付先进入 awaiting_review。只有获得用户明确确认，才能 task accept，填写来源和说明。
9. Relay 不认证人类身份，领取不锁业务文件；不把接入成功当作业务完成。
10. 中断后不按时间猜测会话死亡。recover 必须有原因，旧领取代次不再有效。
11. 交接快照可能过时；接收者重新读取 context 后创建自己的会话、检查领取、继续原任务。
12. 迁移前停止相关工作；完整包要求无活动领取和明确停工。迁移后旧副本停止写入。
    不通过同步盘/网络共享盘多机共写 SQLite；分叉数据库不能自动合并。
